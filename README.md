## プロジェクトの概要

同志社大学 京田辺キャンパスの学生が、話しかけるだけで時間割・課題の締切・帰りの電車・建物の場所を確かめられるチャットボットです。授業「知識情報処理特論」の対話システムの課題として、「この規模のシステムを作れるか」を確かめるために作った試作です。同志社大学の公式サービスではありません。

- 公開版: https://kyotanabe-campus-bot-evjhvgi6yddi7tjdhkk6re.streamlit.app/
- リポジトリ: https://github.com/IkuF0906/kyotanabe-campus-bot （`main` に push すると公開版に自動で反映されます）

特徴

- 対話が入口です。足りない情報は聞き返し、推測を含むときは実行の前に確認します
- ルールベース（キーワード・正規表現）で意図を判定します。LLM・AI の API や有料の API は使っておらず、API キーも要りません
- 時間割・課題・駅の設定は、そのブラウザの localStorage に保存します。サーバーには何も残りません
- 「通じなかった」発話を記録し、評価用発話（dev / test）で正解率を測れます

## システムの全体像

処理の流れ:

```
発話 → bot/nlu.py（意図と日付・授業名などを抽出）
     → bot/dialogue.py（足りない情報は聞き返す／文脈で補う）
     → bot/services.py（時刻の計算などは普通のプログラムで確定的に処理）
     → 返答（views.py が画面に表示）
```

### 対話の状態

```
           ┌──────────── 答えになっていない／別の話題 ────────────┐
           ▼                                                       │
[待機] ─発話→ 意図判定 ─情報が足りる→ 実行して返答 → [待機]        │
                 │                                                  │
                 └─足りない・推測を含む→ [聞き返し中] ─答え→ スロットを埋める
                                         (授業名／締切／教室／確認／候補選択)
```

- 聞き返し中の発話は、まずその質問への答えとして解釈します。答えになっておらず、別の意図と判定できたときは、新しい話題として処理します
- 推測を含むとき（時間割から授業を推定、誤字込みの一致、課題の削除）は、実行の前に必ず確認します

## 開発環境の構築方法

必要なもの: Python 3.11、Git、ブラウザ

1. リポジトリを取得します

   ```
   git clone https://github.com/IkuF0906/kyotanabe-campus-bot.git
   cd kyotanabe-campus-bot
   ```

2. 仮想環境を作って有効にします

   Windows（PowerShell）:

   ```
   py -3.11 -m venv .venv
   .venv\Scripts\Activate.ps1
   ```

   macOS / Linux:

   ```
   python3.11 -m venv .venv
   source .venv/bin/activate
   ```

3. 依存を入れます（テスト・チェック用の道具も一緒に入ります）

   ```
   pip install -r requirements-dev.txt
   ```

4. 起動します

   ```
   streamlit run app.py
   ```

5. ブラウザで http://localhost:8501 を開きます（ふつうは自動で開きます）

GitHub Codespaces で開いた場合は、`.devcontainer/devcontainer.json` の設定で依存の導入と起動まで自動で行われ、ポート 8501 のプレビューが開きます。

## 環境変数とコマンド一覧

### 環境変数

使っていません（コードに `os.environ` や `st.secrets` の読み込みはありません）。API キーなどの秘密の値もありません。設定は `.streamlit/config.toml`（見た目）だけです。

### コマンド

| コマンド | 何をするか |
|---|---|
| `pip install -r requirements-dev.txt` | 依存と開発用の道具（pytest・ruff）を入れる。アプリだけなら `requirements.txt` |
| `streamlit run app.py` | アプリを起動する（http://localhost:8501） |
| `pytest` | すべてのテストを動かす。`-v` でテストごとの結果を表示。失敗したシナリオは、そこまでの会話も表示されます |
| `ruff check .` | 文法の誤り・未使用の名前などを調べる。`--fix` で直せるものは直す |
| `ruff format .` | 書式をそろえる（CI は `ruff format --check .` でそろっているかだけを見ます） |
| `python evaluate.py dev` | 意図判定の正解率と取り違えを表示する。引数は `dev`（既定）／`test`／`all` |

Windows では、日本語の出力で落ちないように `python -X utf8 evaluate.py dev` のように `-X utf8` を付けてください（→ [トラブルシューティング](#トラブルシューティング)）。

サイドバーの「デモ用の時刻」で、アプリの中の時刻を変えられます（デモで「4限の後」などを再現するときに使います）。

## 画面（左のナビ）

どのページも同じデータ（時間割・課題・駅の設定）を共有しています。チャットで登録した課題は、時間割とリマインダーにもすぐ反映されます。

| ページ | 内容 |
|---|---|
| チャット | メインのページです。対話ですべての機能を使えます。「今から帰る」には発車標カードで答えます |
| 時間割 | 週の時間割表（1〜7限。今日の列・受講中・次の授業を強調し、課題がある授業に赤い点）。授業の追加・変更・削除 |
| リマインダー | 締切順の課題一覧、完了チェック、手動追加、.ics 書き出し |
| 電車 | 今いる建物と出発タイミング（今すぐ／N限の後）から、興戸・同志社前のおすすめ便を発車標カードで比べます。種別・行き先、平日／土休日ダイヤ |
| マップ | 建物・駅を選んで地図に表示、Googleマップの道案内、その建物の授業一覧 |

時間割・課題・駅の設定・通じなかった発話の記録は、そのブラウザの localStorage に自動で保存され、再読み込みしても残ります。サーバーには残らないので、他の人のデータと混ざりません。サイドバーの「保存データを消す」で初期状態に戻ります。チャットの履歴は保存しません。

サイドバーの「通じなかった発話」には、意図を判定できなかった発話と、チャットで「通じなかった」を押した発話が貯まります（→ [ルールの改善手順](#ルールの改善手順)）。

## 話しかけ方の例

はい／いいえや選択肢を聞くときは、返答の下にボタンが出ます（押すとその文を送ったのと同じです。文字で答えても構いません）。聞き返しの途中でも「キャンセル」でやめられます。

| 発話 | 動き |
|---|---|
| 月曜2限に線形代数を追加 / 火3はデータ構造、知真館TC1-201 | 時間割に登録（教室がなければ聞き返し、既に授業があれば置き換えを確認） |
| 金1消して | 確認してから時間割から削除 |
| 月曜5限は？ / 水2どこ？ | その時限の授業・教室の場所 |
| 今日レポートあった、15日まで | 時刻と時間割から授業を推定 → 確認 → 登録 |
| レポート出た | 授業を推定し、締切を聞き返す（「いいえ」で授業名を聞き直す） |
| 線型代数のレポート、20日まで | 誤字を近い授業名（線形代数）に直し、確認してから登録 |
| 課題一覧 / 今週の締切は？ / 来週の課題 / 線形代数の課題ある？ | 登録済みの課題（期間・授業で絞り込み） |
| 線形代数のレポート出した / 課題終わった | 課題を完了に（候補が複数なら選ぶ。「出したっけ？」は確認として一覧を返す） |
| データベースの課題消して | 確認してから課題を削除 |
| 今から帰る / 4限のあと帰る / 興戸から帰る | 今いる建物から駅までの徒歩時間を足して、乗れる電車を3本 |
| いつも興戸の奈良方面に設定 / 最寄りは同志社前にして | 帰りの駅・方面を変更 |
| 次の授業は？ / 明日の時間割 / 月曜の授業 | 時間割 |
| 情報メディア館どこ？ / 次の教室どこ？ / 最寄り駅はどこ？ | 地図表示と Googleマップの徒歩ルートへのリンク |

## 表記ゆれ・誤字

- 全角／半角（NFKC）、ひらがな／カタカナ、英字の大小は同じとみなします
- 授業名・建物名は、編集距離で誤字を許します。4文字は同じ長さで1文字違い、5〜6文字は1文字の違い・抜け・余分、7文字以上は2文字までです。3文字以下（知真館・香知館など）は完全一致だけです
- 誤字込みで一致したときは「〇〇のことですか」と確認します（「情報理論」を「情報倫理」と取り違えないように、短い名前ほど厳しくしています）

## データ

| ファイル | 状態 |
|---|---|
| `data/periods.json` | 時限（1〜7限）。同志社大学 京田辺校地の講時です（2026年度の学部時間割表で確認） |
| `data/trains.csv` | **ダミー**です。形式は `station,direction,daytype,time,type,dest`（daytype は weekday / saturday / holiday。saturday が無い駅は holiday を使います） |
| `data/places.json` | 座標は OpenStreetMap から取りました。徒歩分は、興戸が「正門→興戸 15分（メンバーの実測・速め）＋建物→正門の推定」、同志社前は直線距離からの**推定値**です。電車の計算では、どちらにも余裕として2分足します（`services.WALK_MARGIN`） |
| `data/timetable.json` | 初期の時間割（**ダミー**）です |

ダイヤは日付から判定します。日曜・祝日（振替休日を含む。`jpholiday`）・12/30〜1/3 は休日ダイヤ、土曜は土曜ダイヤ（無ければ休日ダイヤ）です。

**時刻表の実データについて**: JR西日本の時刻表ページには「時刻データを無断で転載・複写し、又は…加工することも禁じます」と書かれています（データの元は交通新聞社の「JR時刻表」）。このリポジトリと公開版は誰でも見られるので、実データを入れるなら、許諾を得るか、リポジトリと公開アプリを非公開にしてから入れてください。

## 評価

`data/eval/utterances.csv` に、意図ごとの発話を dev（ルールの改善に使う）と test（改善には使わず評価だけ）に分けて置いています。

| 版 | dev（62発話） | test（61発話） |
|---|---|---|
| 改善前（コミット 25b6ef4） | 72.6% | 75.4% |
| 現在 | 100% | 93.4% |

test で残っている間違い（`python evaluate.py test` で確認できます）:「今日までの課題は」→登録、「レポート出しといた」→登録、「月曜日の3コマ目にデータベース論入れといて」→時間割の質問、「どう使えばいい？」→不明。test を見てルールを直すと評価の意味がなくなるので、直すときはこれらと似た発話を dev に足してから直してください。

## ルールの改善手順

1. 利用者に公開版を使ってもらいます。的外れな返答には「通じなかった」を押してもらいます
2. サイドバーの「通じなかった発話」から CSV を書き出し、「正解の意図」の列を埋めます
3. 埋めた発話を `data/eval/utterances.csv` に `dev` として追加します
4. `python evaluate.py dev` で間違いを確かめ、`bot/nlu.py` のルールを直します
5. `pytest` で他の会話を壊していないか確かめ、最後に `python evaluate.py test` で評価します

## 見た目の方針

[unslop](https://github.com/heydamir/unslop)（Damir Sokolovsky, CC BY 4.0）の手順で整えました。設定は `.streamlit/config.toml` にあります。

- 背景・枠・文字はグレー系です。強調色は同志社パープル `#550071` だけで、主要ボタン・選択中・おすすめ便の時刻・受講中に使います
- アイコンは絵文字ではなく Material Symbols の線アイコンです
- 時刻はすべて等幅数字（JetBrains Mono）に方面・時限のラベルを添えます。これがこのアプリの「印」です
- 文字は Noto Sans JP の 400 / 500 です

## リマインドの方針

- 画面を開いたとき、明日までの締切を上部に表示します
- 「リマインダー」タブから課題を `.ics` で書き出し、スマホのカレンダーに取り込むと、締切前日の 18:00 に通知されます

## トラブルシューティング

| 症状 | 原因 | 直し方 |
|---|---|---|
| Windows で `evaluate.py` などの出力が文字化けする、または `UnicodeEncodeError` で落ちる | Python の出力の文字コードが UTF-8 でなく（cp932）、日本語や記号をうまく出せない | `python -X utf8 evaluate.py dev` のように `-X utf8` を付ける |
| Windows で `pip install -r requirements.txt` が `UnicodeDecodeError: 'cp932' codec can't decode` で落ちる | 古い pip が requirements の日本語（ASCII 以外の文字）を cp932 として読もうとする | requirements のコメントは英語（ASCII）だけで書く。`python -m pip install -U pip` で pip を上げても直ります |
| CI（GitHub Actions）が `ruff format --check` で失敗する | 書式がそろっていないファイルがある | 手元で `ruff format .` を実行してから push する |
| 起動時に `ModuleNotFoundError: No module named 'jpholiday'`（や `pytest`・`ruff` が見つからない） | 依存を足す前の環境のまま | `pip install -r requirements-dev.txt` をやり直す |
| 時間割や課題が別の端末・別のブラウザに出ない | 保存先がそのブラウザの localStorage だけのため（仕様） | 同じブラウザで使う。シークレットウィンドウでは閉じると消えます |
| フォントが標準のものになる／地図が出ない | Google Fonts・Leaflet（jsDelivr）・OpenStreetMap をネットから読むため、オフラインだと読めない | ネットにつながった状態で開く |
| push したのに公開版が変わらない／エラーになる | Streamlit Community Cloud の再デプロイ中か、依存の導入に失敗している | 少し待ってから再読み込みする。直らなければ Streamlit Community Cloud の管理画面でログを見る |
