# 京田辺キャンパスbot（試作版）

対話を入口にして、時間割・課題リマインド・帰りの電車・建物の場所にアクセスできるチャットボット。
LLM・外部APIを使わないルールベースで、無料・APIキー不要で動く。同志社大学の公式サービスではない（授業の課題として作った非公式の試作）。

## 動かし方

```
pip install -r requirements.txt
streamlit run app.py          # ブラウザで開く
python test_dialogue.py       # 対話シナリオと部品の確認（-v で対話の全文を表示）
python evaluate.py dev        # 意図判定の正解率（dev / test / all）
```

サイドバーの「デモ用の時刻」で時刻を変えられる（デモで「4限の後」などを再現する用）。

時間割・課題・駅の設定・通じなかった発話の記録は、そのブラウザの localStorage に自動で保存され、再読み込みしても残る（サーバーには残らないので、他の人と混ざらない）。サイドバーの「保存データを消す」で初期状態に戻る。チャットの履歴は保存しない。

## 画面（左のナビ）

どのページも同じデータ（時間割・課題・駅の設定）を共有している。チャットで登録した課題は、時間割とリマインダーにもすぐ反映される。

| ページ | 内容 |
|---|---|
| チャット | メイン。対話ですべての機能を使える。「今から帰る」は発車標カードで答える |
| 時間割 | 週の時間割表（1〜7限。今日の列・受講中・次の授業を強調、課題がある授業に赤い点）。授業の追加・変更・削除 |
| リマインダー | 締切順の課題一覧、完了チェック、手動追加、.ics 書き出し |
| 電車 | 今いる建物と出発タイミング（今すぐ／N限の後）から、興戸・同志社前のおすすめ便を発車標カードで比較。種別・行き先、平日／土休日ダイヤ |
| マップ | 建物・駅を選んで地図表示、Googleマップの道案内、その建物の授業一覧 |

サイドバーの「通じなかった発話」には、意図を判定できなかった発話と、チャットで「通じなかった」を押した発話が貯まる（→ [ルールの改善手順](#ルールの改善手順)）。

## 話しかけ方の例

はい／いいえや選択肢を聞くときは、返答の下にボタンが出る（押すとその文を送ったのと同じ。文字で答えてもよい）。聞き返しの途中でも「キャンセル」でやめられる。

| 発話 | 動き |
|---|---|
| 月曜2限に線形代数を追加 / 火3はデータ構造、知真館TC1-201 | 時間割に登録（教室がなければ聞き返す。既に授業があれば置き換えを確認） |
| 金1消して | 確認してから時間割から削除 |
| 月曜5限は？ / 水2どこ？ | その時限の授業・教室の場所 |
| 今日レポートあった、15日まで | 時刻と時間割から授業を推定 → 確認 → 登録 |
| レポート出た | 授業を推定し、締切を聞き返す（「いいえ」で授業名を聞き直す） |
| 線型代数のレポート、20日まで | 誤字は近い授業名（線形代数）に直し、確認してから登録 |
| 課題一覧 / 今週の締切は？ / 来週の課題 / 線形代数の課題ある？ | 登録済みの課題（期間・授業で絞り込み） |
| 線形代数のレポート出した / 課題終わった | 課題を完了に（候補が複数なら選ぶ。「出したっけ？」は確認として一覧を返す） |
| データベースの課題消して | 確認してから課題を削除 |
| 今から帰る / 4限のあと帰る / 興戸から帰る | 今いる建物→駅の徒歩時間を足して、乗れる電車を3本 |
| いつも興戸の奈良方面に設定 / 最寄りは同志社前にして | 帰りの駅・方面を変更 |
| 次の授業は？ / 明日の時間割 / 月曜の授業 | 時間割 |
| 情報メディア館どこ？ / 次の教室どこ？ / 最寄り駅はどこ？ | 地図表示＋Googleマップの徒歩ルートリンク |

## 構成

```
app.py              入口：左のナビゲーション、デモ用の時刻、保存の呼び出し
storage.py          時間割・課題・設定をブラウザ（localStorage）に保存・復元
views.py            各ページの画面（発車標カード、通じなかった発話の記録もここ）
.streamlit/         テーマ設定（色・フォント）
bot/mapview.py      地図の描画（Leaflet + OpenStreetMap）
bot/nlu.py          意図判定（キーワード・正規表現）、日付・時限・期間の抽出、表記ゆれ（かな・誤字）
bot/dialogue.py     対話管理：意図ごとの処理、聞き返し（スロットフィリング）、確認
bot/services.py     データ読み込み、時間割・電車（ダイヤ判定）・地図・.ics の処理
data/               時限は公式、それ以外はダミー／推定（下の「データ」）
data/eval/          意図判定の評価用発話（dev / test）
test_dialogue.py    対話シナリオと部品の確認
evaluate.py         意図判定の正解率・取り違えの集計
```

処理の流れ: 発話 → `nlu`（意図と日付・授業名などを抽出）→ `dialogue`（足りない情報は聞き返す／文脈で補う）→ `services`（時刻計算などは普通のプログラムで確定的に処理）→ 返答

### 対話の状態

```
           ┌──────────── 答えになっていない／別の話題 ────────────┐
           ▼                                                       │
[待機] ─発話→ 意図判定 ─情報が足りる→ 実行して返答 → [待機]        │
                 │                                                  │
                 └─足りない・推測を含む→ [聞き返し中] ─答え→ スロットを埋める
                                         (授業名／締切／教室／確認／候補選択)
```

- 聞き返し中の発話は、まずその質問への答えとして解釈する。答えになっておらず、別の意図と判定できたときは、新しい話題として処理する
- 推測を含むとき（時間割から授業を推定、誤字込みの一致、課題の削除）は、実行の前に必ず確認する

### 表記ゆれ・誤字

- 全角／半角（NFKC）、ひらがな／カタカナ、英字の大小は同じとみなす
- 授業名・建物名は、編集距離で誤字を許す。4文字は同じ長さで1文字違い、5〜6文字は1文字の違い・抜け・余分、7文字以上は2文字まで。3文字以下（知真館・香知館など）は完全一致のみ
- 誤字込みで一致したときは「〇〇のことですか」と確認する（「情報理論」を「情報倫理」と取り違えないように、短い名前ほど厳しくしている）

## 評価

`data/eval/utterances.csv` に、意図ごとの発話を dev（ルールの改善に使う）と test（改善には使わず評価だけ）に分けて置いている。

| 版 | dev（62発話） | test（61発話） |
|---|---|---|
| 改善前（コミット 25b6ef4） | 72.6% | 75.4% |
| 現在 | 100% | 93.4% |

test で残っている間違い（`python evaluate.py test` で確認）：「今日までの課題は」→登録、「レポート出しといた」→登録、「月曜日の3コマ目にデータベース論入れといて」→時間割の質問、「どう使えばいい？」→不明。test を見てルールを直すと評価の意味がなくなるので、直すときはこれらと似た発話を dev に足してから直す。

## ルールの改善手順

1. 利用者に公開URLを使ってもらう。的外れな返答には「通じなかった」を押してもらう
2. サイドバーの「通じなかった発話」から CSV を書き出し、「正解の意図」の列を埋める
3. 埋めた発話を `data/eval/utterances.csv` に `dev` として追加する
4. `python evaluate.py dev` で間違いを確認し、`bot/nlu.py` のルールを直す
5. `python test_dialogue.py` で他の会話を壊していないか確認し、最後に `python evaluate.py test` で評価する

## データ

| ファイル | 状態 |
|---|---|
| `data/periods.json` | 時限（1〜7限）。同志社大学 京田辺校地の講時（2026年度の学部時間割表で確認） |
| `data/trains.csv` | **ダミー**。形式は `station,direction,daytype,time,type,dest`（daytype は weekday / saturday / holiday。saturday が無い駅は holiday を使う） |
| `data/places.json` | 座標は OpenStreetMap。徒歩分は、興戸が「正門→興戸 15分（メンバー実測・速め）＋建物→正門の推定」、同志社前は直線距離からの**推定値**。電車の計算では、どちらにも余裕として2分足す（`services.WALK_MARGIN`） |
| `data/timetable.json` | 初期の時間割（**ダミー**） |

ダイヤは日付から判定する：日曜・祝日（振替休日を含む。`jpholiday`）・12/30〜1/3 は休日ダイヤ、土曜は土曜ダイヤ（無ければ休日ダイヤ）。

**時刻表の実データについて**：JR西日本の時刻表ページには「時刻データを無断で転載・複写し、又は…加工することも禁じます」と書かれている（データの元は交通新聞社の「JR時刻表」）。このリポジトリと公開URLは誰でも見られるので、実データを入れるなら、許諾を得るか、リポジトリと公開アプリを非公開にしてから入れる。

## 見た目の方針

[unslop](https://github.com/heydamir/unslop)（Damir Sokolovsky, CC BY 4.0）の手順で整えた。設定は `.streamlit/config.toml`。

- 背景・枠・文字はグレー系。強調色は同志社パープル `#550071` だけで、主要ボタン・選択中・おすすめ便の時刻・受講中に使う
- アイコンは絵文字ではなく Material Symbols の線アイコン
- 時刻はすべて等幅数字（JetBrains Mono）＋方面・時限のラベル。これがこのアプリの「印」
- 文字は Noto Sans JP の 400 / 500。フォントは Google Fonts から読むので、オフラインだと標準フォントになる

## リマインドの方針

- 画面を開いたとき、明日までの締切を上部に表示
- 「リマインダー」タブから課題を `.ics` で書き出し → スマホのカレンダーに取り込むと、締切前日18:00に通知
